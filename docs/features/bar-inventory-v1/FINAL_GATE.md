# Bar Inventory V1 — final gate (BI-11)

**Verdict: GO for the Bar Inventory cycle on `development`**, with the owner decisions listed under "Needs the owner". This is an integration gate, **not a release**: nothing has been merged to `main`, Production is untouched, and the release route stays blocked on #111 / #113.

**Date:** 2026-10-27 · **Baseline:** `development` at `01c0263` (BI-10 merge) · **Branch:** `feature/bar-inventory-bi11-final-gate`

## How the gate was run

1. The full suite on the untouched baseline (to know what "green" was before changing anything): Vitest, 38 pgTAP files, Playwright on all three device projects.
2. Three independent, **read-only** reviews run in parallel — security / RLS / migrations; code correctness (arithmetic, time zones, races, import/export, XLSX guard); accessibility, responsive layout and dependencies. Each had to report only findings with evidence.
3. Every finding was **checked against the code** before acting. Two were reproduced empirically (below) and one was proven on the hosted project.
4. Fixes with regression tests, then the full suite again, then the hosted DEV runs on a DEV-pinned production build.

### Dependencies

- `write-excel-file@4.1.1`, `read-excel-file@9.3.12`, `fflate@0.8.3` are exact-pinned (no `^`/`~`), all MIT, nothing else spreadsheet-like was added (only `read-excel-file`'s own `saxen`, `unzipper-esm`, `worker-f`, MIT, fixed by the lockfile).
- `npm audit --omit=dev` reports **next 16.3.4** (several advisories, fixed by 16.4.3 — including a Server Actions denial-of-service that Bar Inventory's actions are exposed to, like every action in the app) and **zod 4.5.4** (memory exhaustion validating oversized collections, fixed by 4.6.7; reachable in the import actions, which validate before the auth check). Both are non-major bumps that affect the **whole application**, so they are handled as their own change — `fix/security-dependency-bumps` — with the full suite, not folded into this gate. `sharp` and `source-map-js` are not reached.
- No secret or service-role reference exists in Bar Inventory client code.

3. Awareness: the **next** and **zod** security bumps go in a separate change before any release.
