## Security and roles

- Authorization is database-authoritative. Every management RPC calls `recipes_begin` (`auth.uid()` plus an active management membership, else `42501`), pins `search_path`, scopes by organization, and grants `execute` to `authenticated` only. Tables are SELECT-only for `authenticated`, nothing for `anon`.
- Staff: active recipes only (RLS and an explicit server filter), no management controls rendered, direct RPC and Server Action replays with Staff's own session are denied (hosted editor, management and images flows), Storage insert/delete denied, archived signing denied.
- Foreign organization: zero rows on read, `42501` on write, signing and Storage denied, composite FKs as the second line (pgTAP 0043/0044/0045, hosted DB suites; new hosted assertions for the batched path).
- No `dangerouslySetInnerHTML`, no service-role client and no Realtime in `src/features/recipes`; no tracked `.env`, token or key patterns; the PROD ref appears only in three test/guard files that refuse it; `check:local-paths` OK.

## Observations (not defects, not blocking)

- **O1.** Staff's detail read is several queries, not one transaction. A Staff page load that straddles an archive commit can briefly show the title with "No recipe details are available yet" and a placeholder instead of "Recipe not found". Archived content never reaches Staff; the next navigation is correct. Left as is.
- **O2.** The view preference is per device (browser), not per user, as specified (UI_UX_PLAN). On a shared tablet the last choice wins.
- **O3.** Picture Book card images use the recipe name as `alt` (STORAGE_PLAN S-12) inside a link that also shows the name, so a screen reader may announce the name twice. The contract is locked; no change.
- **O4.** Contrast was not measured with an automated tool in this gate; the surfaces reuse design-system tokens that earlier gates reviewed. Hosted browser flows run on desktop Chromium only (repository convention); WebKit tablet and mobile are covered by the local matrix.
