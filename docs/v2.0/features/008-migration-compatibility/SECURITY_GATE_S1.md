## 2. Shared session validation (`session_id` fallback)

**Claim under review (B1 P2-1):** a JWT with no `session_id` claim is accepted on the ban-only path.

Facts established:

1. **The helpers are not uniform.** Deployed `private.*_live_session` helpers split: **`tasks` and `tips` require a matching live `auth.sessions` row** (no `session_id` → denied); **`schedule`, `payroll`, `inventory` (shared by Recipes), `attendance` and `kiosk` accept a token with no `session_id` after the ban check.** B1's "identical to every other helper / six modules" was inaccurate: it is five helpers with the fallback and two without.
2. **Supported sessions always carry the claim.** A real GoTrue (v2.186.0) password sign-in token and its refreshed successor both contain `session_id`, stable across refresh (checked on the local stack; claim names only, no token values recorded). The kiosk obtains employee tokens through `signInWithPassword` (`kiosk-clock-actions.ts:410`), so they are real GoTrue sessions.
3. **The repository never mints a user JWT.** No `SignJWT` / `jsonwebtoken` / `jose` / JWT-secret use in `src/`, `scripts/` or `supabase/functions/` (grep). Without the signing key a token cannot reach PostgREST.
4. **Removing the fallback would not break supported authentication:** Tasks and Tips already run the strict form on every request. (Hosted DEV's GoTrue version was not read in S1; the local evidence is for v2.186.0.)
5. **Coverage:** the no-`session_id` path is exercised only incidentally — 35 of the 69 pgTAP files that set JWT claims never mention `session_id`. There is no dedicated assertion "a token without `session_id` is (still) accepted/denied".

**Conclusion:** no authentication bypass is demonstrated — the only token that could exercise the fallback is one signed with the project's JWT secret, whose holder already has full control. **Not blocking.** Tracked as separate hardening item **H-S1 (P3)**: redefine the five helpers in the strict form of `tasks_live_session` in one forward-only migration, then give every affected pgTAP/real-JWT fixture a `session_id` + live `auth.sessions` row (the main cost). Not needed for B2 or V2-009; propose it as a post-V2-009 cross-module change needing its own owner approval (D-11).
