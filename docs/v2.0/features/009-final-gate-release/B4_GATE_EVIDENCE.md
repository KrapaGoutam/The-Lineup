### 3.1 Seam test — what it proves (B1 lifecycle × B3 personal PIN)

1. **Deactivation is organization-scoped for PIN login.** After `team_set_member_active(A, false)` the PIN login to A returns 401 and to B returns 200 with the same PIN; no Auth ban is written; the credential row in A is inactive and in B active. Reactivation restores A.
2. **Rotation while deactivated stays consistent.** A reset applied while A is inactive updates the inactive credential's locator; after reactivation the new PIN works in A and the old one nowhere.
3. **The deactivation/sync race fails closed.** With an active credential forced onto an inactive membership (the outcome of a lost race) the login returns 401/403 and issues no user; the same person still reaches B.
4. **`team_add_member` + login sync.** The RPC creates no credential; a login in B syncs one for A and A then works; a membership deactivated before first sync never receives a credential.
