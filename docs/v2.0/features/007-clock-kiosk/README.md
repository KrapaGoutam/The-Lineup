## 1. Executive Summary & Mission

Feature **V2-007 (Clock In / Clock Out Kiosk)** delivers a dedicated, touch-first, shared-tablet kiosk surface for restaurant locations. The kiosk allows on-site employees to quickly clock in, clock out, manage meal/rest breaks, and inspect or print personal monthly attendance timesheets using a 4-digit PIN.

### Core Architectural Principles

1. **Physical Tablet Trust via In-App Pairing:** Tablets are paired via one-time 6-character alphanumeric codes generated by authorized location managers. No client-side GPS, IP geolocation, or spoofable headers are used to determine restaurant location.
2. **Server-Authoritative Location Binding:** Every device is registered in `public.kiosk_devices` bound strictly to `(organization_id, location_id)`. The server resolves location strictly from the server-stored device record.
3. **Shared-Tablet Isolation & Ephemeral Authentication:**
   - Tablets hold a long-lived, HttpOnly device cookie (`lineup_kiosk_device`, 1-year TTL) containing a 256-bit cryptographically secure random token (hashed via SHA-256 in PostgreSQL).
   - Employee PIN verification issues an ephemeral, HMAC-SHA256 signed session cookie (`lineup_kiosk_session`, 3-minute TTL).
   - In-memory Supabase client (`persistSession: false`) executes canonical attendance RPCs; no Supabase credentials, tokens, or PINs are ever stored in `localStorage`, `sessionStorage`, or client state.
4. **Zero Duplicate Employee/PIN Roster:** Reuses existing `public.passcode_credentials` and canonical attendance RPCs (`attendance_clock_in`, `attendance_clock_out`, `attendance_break_start`, `attendance_break_end`).
5. **Fail-Closed Revocation & Reassignment Invalidation:** If a kiosk is revoked or relocated in the database, all active and pending operations fail closed immediately.
6. **Shared-Tablet Privacy:** Automatic 45-second inactivity timeout, explicit "Finish" state purge, and print isolation (`@media print`).

## 3. Database Schema & Migration Architecture

**Migration File:** `supabase/migrations/20261111120000_kiosk_device_registration.sql`

### 3.1 Tables

#### `public.kiosk_devices`

Stores physical kiosk device registrations.

- `id` (uuid, PK, default `gen_random_uuid()`)
- `organization_id` (uuid, FK `organizations(id)` ON DELETE CASCADE, NOT NULL)
- `location_id` (uuid, FK `locations(id)` ON DELETE RESTRICT, NOT NULL)
- `device_name` (text, NOT NULL)
- `device_token_hash` (text, UNIQUE, NOT NULL) — SHA-256 hash of device credential
- `status` (text, default `'active'`, check: `'active' | 'revoked'`)
- `revoked_at` (timestamptz, nullable)
- `revoked_by` (uuid, FK `auth.users(id)`, nullable)
- `revoked_reason` (text, nullable)
- `last_active_at` (timestamptz, default `now()`)
- `created_at` (timestamptz, default `now()`)
- `updated_at` (timestamptz, default `now()`)

#### `public.kiosk_pairing_codes`

Stores short-lived pairing codes.

- `id` (uuid, PK, default `gen_random_uuid()`)
- `organization_id` (uuid, FK `organizations(id)` ON DELETE CASCADE, NOT NULL)
- `location_id` (uuid, FK `locations(id)` ON DELETE CASCADE, NOT NULL)
- `code_hash` (text, UNIQUE, NOT NULL) — SHA-256 hash of 6-character code
- `created_by` (uuid, FK `auth.users(id)`, NOT NULL)
- `expires_at` (timestamptz, NOT NULL) — 15 minutes from creation
- `consumed_at` (timestamptz, nullable)
- `consumed_by_device_id` (uuid, FK `kiosk_devices(id)`, nullable)
- `attempt_count` (int, default 0, check `<= 5`)
- `created_at` (timestamptz, default `now()`)

### 3.2 Security & RLS

- Both tables have `ALTER TABLE ... ENABLE ROW LEVEL SECURITY;` and `ALTER TABLE ... FORCE ROW LEVEL SECURITY;`.
- Management operations are guarded by `kiosk_can_manage_location(location_uuid)`.
- Explicit grants restricted to `authenticated` role (`SELECT, INSERT, UPDATE` on devices/codes); `anon` role has **zero** table permissions.

### 3.3 Database Functions & RPCs

1. `public.kiosk_can_manage_location(p_location_id uuid) RETURNS boolean`:
   Verifies whether the calling user is an Owner, General Manager, or Location Manager for the target location.
2. `public.kiosk_generate_pairing_code(p_location_id uuid, p_code_hash text) RETURNS uuid`:
   Generates a pairing code record expiring in 15 minutes. Requires manager capability.
3. `public.kiosk_consume_pairing_code(p_code_hash text, p_device_name text, p_device_token_hash text) RETURNS TABLE(...)`:
   Atomically verifies validity, checks attempt count (locks at 5), marks code consumed, and inserts the `kiosk_devices` row in a single atomic transaction.
4. `public.kiosk_revoke_device(p_device_id uuid, p_reason text) RETURNS boolean`:
   Revokes an active device with reason attribution.
5. `public.kiosk_rename_device(p_device_id uuid, p_new_name text) RETURNS boolean`:
   Updates device friendly name.
6. `public.kiosk_reassign_device(p_device_id uuid, p_new_location_id uuid) RETURNS boolean`:
   Relocates device within the same organization.

## 4. Cryptographic & Cookie Security Architecture

### 4.1 Token Specifications

- **Device Credential Token:** 32-byte (256-bit) cryptographically secure random string (`kiosk_dev_...`). Transmitted only over HTTPS. Stored on device in HttpOnly cookie `lineup_kiosk_device`. Stored in DB as SHA-256 hex digest (`device_token_hash`).
- **Pairing Code:** 6-character uppercase alphanumeric string excluding ambiguous characters (`0, O, 1, I`). Hashed via SHA-256 hex digest (`code_hash`).
- **HMAC Session Token:** JSON payload signed with HMAC-SHA256 using server secret (`SUPABASE_JWT_SECRET` / `NEXTAUTH_SECRET`). Contains `{ employeeId, organizationId, locationId, employeeName, expiresAt }`. Transmitted via HttpOnly cookie `lineup_kiosk_session` with a 3-minute TTL.

### 4.2 Shared-Tablet Protection Model

```
┌────────────────────────────────────────────────────────┐
│                     Shared Tablet                      │
│                                                        │
│  HttpOnly Cookie: lineup_kiosk_device                  │
│  (1-Year TTL, Device Token)                            │
│                                                        │
│  HttpOnly Cookie: lineup_kiosk_session                 │
│  (3-Minute TTL, HMAC-SHA256 Signed Employee Session)   │
│                                                        │
│  No localStorage / sessionStorage tokens               │
│  No Supabase Auth session persisted                    │
└────────────────────────────────────────────────────────┘
```

## 5. Employee PIN Authentication & Attendance Delegation

### 5.1 Verification Flow

1. **Device Resolution:** Device cookie read and verified against `public.kiosk_devices` where `status = 'active'`. Resolves authoritative `(organization_id, location_id)`.
2. **Dual Rate-Limiting:**
   - Kiosk Device Level: Maximum 5 failed attempts per 15 minutes.
   - Organization Level: Maximum 30 failed attempts per 30 minutes.
3. **PIN Lookup:** Hashes PIN and resolves employee via `public.passcode_credentials`.
4. **Roster Verification:** Validates employee has an active assignment in `location_memberships` for the kiosk's location.
5. **Module Verification:** Checks location configuration has internal attendance enabled (`internal_the_lineup`).
6. **Session Issuance:** Sets short-lived HMAC session cookie (`lineup_kiosk_session`).

### 5.2 Attendance Operations

- All clock in, clock out, and meal/rest break mutations delegate directly to canonical native attendance RPCs:
  - `attendance_clock_in(p_location_id, p_employee_id, ...)`
  - `attendance_clock_out(p_shift_id, ...)`
  - `attendance_break_start(p_shift_id, p_break_type)`
  - `attendance_break_end(p_break_id)`
- Server monotonic timestamps are used exclusively; device client clock is never trusted for attendance records.

## 7. Guardrails Compliance

- **Tenant Scoping:** All operations strictly scoped by `organization_id` and `location_id`.
- **Financial Activation:** Native financial features strictly disabled (`enabled: false`).
- **Module Enforcement:** Backend module enforcement remains in staged mode (`mode: 'staged'`).
- **No Client Spoofing:** Location binding is 100% server-authoritative.
- **Fail-Closed Operations:** Device revocation halts all active sessions instantly.
