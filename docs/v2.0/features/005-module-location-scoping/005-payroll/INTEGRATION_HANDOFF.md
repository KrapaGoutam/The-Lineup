# Feature V2-005.005: Payroll Location Scoping — Integration Handoff

## 1. Overview & Scope Contract

- Feature: V2-005.005 — Payroll Location Scoping
- Module Classification: HYBRID
- Data ownership:
  - Organization level: `payroll_settings` (default rate), `payroll_rates` (overrides), org-wide liability reporting.
  - Location level: `payroll_periods` (with optional `location_id`), payments, adjustments, and branch-specific dashboards.
  - Self level: Regular staff access restricted to own locked/paid periods and confirmed disbursements via `attendance_identity_links`.

## 2. Attendance Location Provenance & Double-Count Prevention

- External Neon attendance data lacks physical restaurant tags.
- Employees assigned to multiple branches cannot be generated by a single branch manager. This operation fails closed, requiring an organization manager.
- Unique period constraint `UNIQUE(organization_id, neon_user_id, period_month)` is strictly preserved.
- Historical periods retain `location_id IS NULL` without destructive backfilling or reassignment.

## 3. Migration & DB Changes

- Forward-only migration adding `location_id` to `payroll_periods`.
- Attribution FK repair: actor columns re-pointed from `memberships(organization_id, profile_id)` to `profiles(id)` with actor identity triggers, allowing Overall administrators without tenant memberships to manage payroll.
- RLS policies hardened with `private.payroll_*` helpers.
- `unconfirm_payroll_payment` updated to verify manager authority over target period.
- Backend module enforcement restrictive policy on `payroll_periods`.
