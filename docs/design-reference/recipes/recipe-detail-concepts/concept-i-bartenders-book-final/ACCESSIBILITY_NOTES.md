# View I — Accessibility Notes

Notes for the implementation. The mockup is not an accessible build; these are the requirements it should meet.

## Headings and landmarks

- `h1` = recipe name. Keep the existing behaviour that moves focus to it on mount (`tabIndex={-1}`).
- `h2` = page label ("Perfect", "House"). Keep ids `recipe-variant-perfect-heading` and `recipe-variant-house-heading` and `tabIndex={-1}` so existing links and tests still work.
- `h3` = Ingredients, Preparation.
- The spread is a `div`; each page is an `article` with `aria-labelledby` pointing at its `h2`. Optional: wrap both in a `section` labelled "Recipe builds".
- The figure is a `figure` with a `figcaption`; the shared glass/rim text is real text, not part of the image.

## Comparing Perfect and House without sight or colour

- Order in the DOM is Perfect, spine, House. Keep this order.
- Distinction is not colour only: hollow vs filled marker (decorative), the words "Perfect" / "House", and the sub-labels.
- "N differences" is text. Its `title` is not enough for touch and screen readers: provide the detail also as visually hidden text (for example "Differs from Perfect: ingredients, garnish, steps") and make the label focusable (`tabindex="0"`) as in the reference.
- Do not tint rows. The current screen adds "(differs in House recipe)" to Perfect rows for screen readers; if the owner wants that kept, keep it as `sr-only` text without visual change.

## Quantities

- Each ingredient row reads naturally as "Bourbon, 2 oz". The split whole / fraction / unit spans are visual: keep them inline text in DOM order so they read as one phrase ("0.25 oz").
- Use `font-variant-numeric: tabular-nums`.

## Steps

- Real `ol`/`li`. Step numerals are generated by CSS counters, so the list semantics provide the numbers. Do not duplicate them in text.
- Verb emphasis uses `<b>` or `<strong>`; screen readers may announce it; keep it to the verb.

## Bartender Note

- The bulb icon is decorative: `aria-hidden="true"`, `focusable="false"`.
- Label text "BARTENDER NOTE" is real text and names the note (`aside` with `aria-labelledby`).
- Mobile collapsed note: `role="button"`, `tabIndex=0`, `aria-expanded`, Enter and Space toggle. Collapsed text must remain available to assistive tech (it is only visually clamped).
- Never rely on italic or colour to convey that it is a note.

## Unit toggle

- Two buttons in a `role="group"` labelled "Measurement units", `aria-pressed` on the active one. Announce changes politely (`aria-live="polite"` region or rely on the pressed state).
- Hit area ≥ 44 px on touch.

## Keyboard and focus

- Order: Back, Edit, unit toggle, difference label, mobile notes.
- Focus ring: 2px solid `--k-acc` with 2px offset on links, buttons, and focusable labels (contrast on both themes is ≥ 3:1; verify in the real app).
- Do not remove the existing focus-visible styling.

## Contrast

- Measured values are in `VIEW_I_TOKENS.md`. Body text 8.8–14.6. One recorded exception: Light 10 px "BARTENDER NOTE" label at 4.47 (needs a decision).
- Do not use `--k-mute` for anything smaller than the sizes in the mockup.

## Touch targets

- Back and Edit: ≥ 44 px tall on mobile (the mockup uses 44).
- Note buttons on mobile: whole note area.
- Unit toggle: enlarge hit area to 44 px even if the visual is smaller.

## Motion

- No required animation. If the mobile note expands with a transition, wrap it in `@media (prefers-reduced-motion: no-preference)`; the reference CSS disables motion under `reduce`.

## Image

- Real image: `alt` = recipe name (existing `RecipeImage` behaviour).
- Placeholder (Martini icon): `aria-hidden` icon; image container keeps `data-testid="recipe-image"`.
- Image is the only copy; do not repeat it in a hidden duplicate for mobile.

## Zoom and text size

- Everything is sized in px in the mockup; production may use rem equivalents. At 200 % zoom the layout will exceed 1366×768 fit; allow scrolling rather than shrinking text. Never clip text.
