# Codebase Audit — 2026-09-05

Read-only discovery pass over `CLAUDE.md`, `AGENTS.md`, `README.md`, and the PRD/spec files, followed by a review of the actual source tree. No code was written or modified as part of this audit.

## 1. Stack, layout, and local run

**Stack** (`package.json`, `docs/TECH_STACK.md`): Next.js 16 (App Router) + React 19 + TypeScript, Tailwind CSS 4, shadcn-style primitives (`src/components/ui/`), Framer Motion, React Hook Form + Zod, `@supabase/ssr` + `@supabase/supabase-js`, Vitest + Testing Library, Playwright, Supabase CLI for pgTAP.

**Layout** matches `docs/ARCHITECTURE.md` almost exactly:

- `src/app/` — root page, `/r/[restaurantSlug]` route, two API route handlers (`api/auth/passcode`, `api/access-requests`), plus `api/auth/signout`.
- `src/components/` — app shell, login screen, shadcn primitives, and an **unused** `dashboard-overview.tsx` (see §3).
- `src/features/` — `auth`, `schedules`, `allocation`, `tips` (each with `domain/` + `components/`), plus retained pure engines in `floor/` and `rotation/`.
- `src/lib/` — Supabase browser/server/admin/proxy clients, `current-user.ts`, `passcode-security.ts`, `demo-data.ts`.
- `supabase/` — two migrations, pgTAP tests, `config.toml`, an intentionally empty `seed.sql`.
- `proxy.ts` at repo root — Next.js 16's session-refresh entrypoint (replaces old `middleware.ts`).

**Local run**: `npm ci`, `cp .env.example .env.local`, `npm run dev` → `localhost:3000`. With `NEXT_PUBLIC_DEMO_MODE=true` (the `.env.example` default), `login-screen.tsx` short-circuits straight to hardcoded `demoAccounts` in `demo-data.ts` — no Supabase project needed. `node_modules` is currently **not installed** in this checkout, so `npm ci` is the first real step.

**Supabase/RLS layer itself** (independent of the UI wiring above) is **fully implemented and well-tested**: both migrations (`20260905065702_initial_schema.sql`, `20260905125418_operational_modules.sql`) define tenant-scoped tables, composite `(id, organization_id)` FKs, RLS on every exposed table, explicit grants (`anon` gets nothing), a `recalculate_tip_pool` `SECURITY INVOKER` function with correct deterministic-remainder math, and two pgTAP suites (`0001_schema.test.sql`, `0002_operational_modules.test.sql`, 11 + 18 assertions) that check RLS-enabled flags and `anon`/`authenticated` privilege boundaries.

**The gap, stated plainly**: the three MVP modules are a fully-designed, well-tested _offline prototype_. None of `schedule-workspace.tsx`, `allocation-workspace.tsx`, or `tip-workspace.tsx` imports a Supabase client, calls a Server Action, or subscribes to Realtime — confirmed by grep and by reading all three files in full. This is self-documented and not hidden: `README.md`'s "Current delivery state" and `docs/ROADMAP.md` Phase 2 item 6 (unchecked: _"Connect the interactive reference UI to hosted Supabase mutations and Realtime subscriptions"_) both say this directly.

## 3. Contradictions found

- **Feature docs overstate status relative to the code.** `docs/features/002-schedule-roster.md`, `003-table-allocation.md`, and `004-tip-split.md` each open with `Status: implemented (interactive reference UI and production schema)`. Read at face value that implies the UI runs against the schema; it doesn't — the schema and the UI are two disconnected, independently-complete halves. `README.md` and `ROADMAP.md` describe this correctly ("interactive reference UI" is separate from "hosted Supabase persistence... require the project credentials"); the three feature docs don't make that separation explicit at the top, which could mislead a reader who only skims the status line.
- **Feature 000's acceptance criteria describe a page the app no longer serves.** `docs/features/000-foundation.md` says the dashboard should render _"Tonight at a glance," "Table rotation," and "Weekly roster"_ — that's `src/components/dashboard-overview.tsx`, which still exists and is fully built, but nothing imports it anymore (confirmed via repo-wide search: 1 match, itself). Both `/` and `/r/[restaurantSlug]` now render `RestaurantOperationsApp` (the passcode-gated shell from Feature 001) instead. `dashboard-overview.tsx` is dead code left over from Feature 000, superseded by Feature 001 but never removed or reconciled in the docs.
- **ARCHITECTURE.md's "Live seating transaction"** describes a `SECURITY INVOKER` Postgres RPC with advisory locking for seating commits. No such function exists in either migration — only `recalculate_tip_pool` exists as an RPC. This is consistent with the "not yet wired" state above, but ARCHITECTURE.md doesn't flag it as aspirational the way ROADMAP.md does.
- No direct contradiction between `AGENTS.md`, `CLAUDE.md`, and `README.md` on process/roles — they're consistent (Claude plans, Codex builds, Gemini critiques, shared rules in `AGENTS.md`).

## 4. External setup required before this runs against real data

1. **Supabase project** (Free tier is sized for): create it, then apply both migrations in `supabase/migrations/` in order (SQL editor or `supabase db push`/CLI).
2. **Env vars** (`.env.local` from `.env.example`): `NEXT_PUBLIC_SUPABASE_URL`, `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY`, `SUPABASE_SECRET_KEY`, `APP_PIN_PEPPER` (≥32 random chars, server-only), `SUPABASE_PROJECT_ID`/`SUPABASE_ACCESS_TOKEN` (CLI/CI only), and set `NEXT_PUBLIC_DEMO_MODE=false`.
3. **Manual bootstrap data** — nothing seeds this automatically (`supabase/seed.sql` is deliberately empty): first Supabase Auth user, `profiles` row, `organizations` row (with matching `slug`), `memberships` row with roles, `locations` row, and a `passcode_credentials` row whose `locator` is `HMAC-SHA256(APP_PIN_PEPPER, organization_id + ":" + passcode)` and whose Auth password equals that same raw passcode — per `docs/DEPLOYMENT.md` step 1.
4. **Generated types**: run `npm run db:types` against the linked project once it exists — `src/types/database.generated.ts` doesn't exist in the repo yet.
5. **Before this is meaningfully useful beyond auth**: someone has to actually wire `schedule-workspace.tsx` / `allocation-workspace.tsx` / `tip-workspace.tsx` to Server Actions + Supabase reads + Realtime, since none of that exists yet (§2/§3) — that's ROADMAP Phase 2 item 6, not a config/env gap.
6. **Local Docker** for `npm run db:test` (pgTAP) — `docs/features/000-foundation.md` notes Docker wasn't available in the original generation environment, so that command should be verified on a Docker-capable machine before relying on it.
7. **Optional**: GitHub remote + Vercel project + `VERCEL_TOKEN`/`VERCEL_ORG_ID`/`VERCEL_PROJECT_ID` if you want the CI/CD pipeline in `docs/CI_CD.md` to actually deploy (currently no remote is configured).
