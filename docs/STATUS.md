## Same-server repeat table (#166 — PR #167 into `development`)

A server who already holds an active table and reaches a **later rotation turn** that is given the same physical table no longer hits the "already assigned" dead end. The **database** decides by turn (board cell, ordered by `rotation_rounds.sequence`): same cell = idempotent retry (no-op); held only in earlier turns = `PT409 same_server_repeat` → dialog **End Previous + Assign / Cancel**, confirmed atomically by `board_end_previous_and_assign` (previous entry ended and kept as history, one active claim, Undo/Redo unchanged); held in the same-or-later turn = still blocked. Cross-server Transfer / End + Assign unchanged; combined assignments end as one lifecycle unit. Migration `20261026150000` (forward-only; **DEV applied, PROD not**). Docs and evidence: `docs/features/same-server-repeat-table/`.

## Canonical numeric table input resolution (#157 — merged into `development`, PR #158, merge commit `f8fa191`)

Owner testing clarified the contract that #153 had set the other way: **typing `1` where the location has a registered `T1` is `T1`**, exactly like choosing `T1` from Floor or Picker. Resolved **server-authoritatively**: one private DB resolver (`private.resolve_table_input`: exact registered label → digits-only `T` + digits → trimmed free text; leading zeros never collapsed; same location only) is reused by `board_assign`, `board_end_and_assign`, displacement and the occupancy trigger, so a stale or different client cannot create a second `1` identity. Combined labels resolve per part (`1 + 2` → `T1 + T2`). Conflicts, same-server, End + Assign, Transfer, Undo/Redo and Recent Activity all operate on the canonical `T1` and its `dining_table_id`. No alias table, no history rewrite, no RLS widening. Migration `20261026120000` (forward-only; **DEV applied, PROD not**). Docs and evidence: `docs/features/table-input-canonical-resolution/`.

## 🛡️ Invariants & Rules Reference

1. **Multi-Tenancy:** All tenant operations scoped by `organization_id` with RLS.
2. **Deterministic Rotation:** Table rotation algorithm is pure; decisions and overrides are persisted separately.
3. **No Moving Occupied Tables:** Floor rebalancing must never move seated/occupied tables.
4. **Overrides Require Auditing:** Any manual assignment or override records user attribution.
5. **Quality Gate:** Before every commit, run `npm run check`, `npm test`, and `npm run build`.
